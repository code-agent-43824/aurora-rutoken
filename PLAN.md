- [x] **Читать сертификат изнутри контейнера, а не из хранилища.** Владелец
  указал на смысловую ошибку модели: перечисление сертификатов через CapiLite
  (`CertOpenSystemStoreA("MY")`) возвращает только **установленные
  (зарегистрированные)** сертификаты. Приложение сертификаты не устанавливает,
  поэтому в этом списке их не будет никогда, и сертификат, физически лежащий
  **внутри контейнера**, так не виден. Заменить/дополнить источник: для каждого
  логического контейнера открывать контекст самого контейнера
  `CryptAcquireContextA(container, provider, type, CRYPT_SILENT)` и читать
  привязанный к ключу сертификат `CryptGetUserKey(AT_KEYEXCHANGE|AT_SIGNATURE)`
  → `CryptGetKeyParam(KP_CERTIFICATE)` → DER, затем `CryptDestroyKey` и
  `CryptReleaseContext`. Расширить минимальный runtime-ABI тремя функциями и
  константами `AT_KEYEXCHANGE`/`AT_SIGNATURE`/`KP_CERTIFICATE`; отсутствие
  символов деградирует к прежнему поведению. **Обязательно `CRYPT_SILENT`**,

  helper; недоступный контейнер остаётся обычным read-only объектом-контейнером

### v1.3 — ключевые контейнеры и PKCS#10 через КриптоПро CSP — В РАБОТЕ с 2026-07-31

Первый этап, где приложение **пишет** через КриптоПро, а не только читает.
Поэтому безопасность фиксируется до кода:

- **Запись — только в отдельном helper-процессе.** Read-only сканирование и
  запись не смешиваются: у записи свой одноразовый режим того же исполняемого
  файла, чтобы падение CSP не уронило интерфейс.
- **PIN-код не передаётся аргументом командной строки** (аргументы видны в
  списке процессов) — только через stdin helper'а. Спрашиваем PIN-код сами и
  передаём в CSP (`PP_KEYEXCHANGE_PIN`/`PP_SIGNATURE_PIN`), как решил владелец
  2026-07-30, а не отдаём на откуп системному диалогу провайдера.
- **Удаление контейнера разрешено только как откат** контейнера, созданного этой
  же операцией, и живёт в одной выделенной функции. Никакого удаления чужих
  контейнеров в v1.3 нет; инвариант проверяется гейтом.
- Read-only инвариант v1.2 переписывается под это: запрещёнными остаются
  `certmgr`/`cryptcp`/shell, смешивание с PKCS#11 и удаление вне отката.

### v0.2 — Вход по PIN и детали токена — ЗАКРЫТА 2026-07-20

Архитектурное решение (конфликт контекстов): `C_Initialize`/`C_Finalize` глобальны для процесса; фоновый опрос `TokenWatcher` и операция логина не должны пересекаться. ### v0.4.1 — Нормальный ввод PIN и NFC-парадигма — ЗАКРЫТА 2026-07-21

Владелец (уточнено ответами 2026-07-21):
- Отдельный **экран ввода PIN с цифровой клавиатурой** + переключение в **текстовый режим** (обычная клавиатура ОС).
- **USB:** после первого ввода PIN приложение **помнит его** до «Разлогиниться» / отключения USB / закрытия приложения.

PIN по NFC **не кэшируется**. **Запись по NFC тоже** — генерация/импорт при NFC запускают свой мастер (ответ владельца «сразу и запись по NFC»). Экспорт — офлайн по снимку (токен не нужен).
